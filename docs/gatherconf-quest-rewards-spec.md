# GatherConf2026 聚落任務與獎勵規格書（初版）

本文件規劃給所有與會者（下稱「旅人」）的任務系統，完成任務可累積點數，在活動現場兌換實體獎勵。任務主題呼應 BBTI（Bunny Builder Type Indicator）的「聚落」世界觀（見 `docs/mbti-quiz-planning.md` §1.1），把整場 GatherConf2026 包裝成一個聚落，讓玩過測驗的人有延續感、還沒玩測驗的人也會被任務引導去玩。

**初版說明**：任務內容與點數門檻是第一版規劃，實際攤位/講座數量、現場兌換動線、獎品內容都需要活動主辦端確認，見第 5 節待確認事項。資料表結構已獨立拆到 `docs/gatherconf-quest-data-model.md`。

---

## 1. 設計原則

- **世界觀延續**：任務、點數、獎勵的命名都沿用「聚落」語彙（旅人、拓荒、聚落據點……），跟 BBTI 測驗是同一套故事，不是另外貼一層活動集章卡。
- **任務分兩大類**：
  - **測驗任務**：跟 BBTI 測驗本身互動（做測驗、分享結果），目的是把測驗導流量轉換成任務參與度。
  - **現場任務**：跟實體活動互動（攤位、講座、社交），目的是帶動現場人流與交流。
- **累積點數兌換，而非單一任務對單一獎品**：每個任務給固定點數，點數累積到門檻兌換對應層級的獎勵，門檻分多層，讓早離場或任務做得少的人也拿得到最基礎的獎勵，不是全有全無。
- **完成認定要能被追蹤**：能在系統裡自動判定的任務（例如做完測驗），優先用系統紀錄；仰賴現場人工認定的任務（例如攤位打卡），需要有明確的認定方式（見第 4 節）。

## 2. 任務清單

| 任務代號 | 任務名稱 | 說明 | 點數 |
|---|---|---|---|
| Q1 | 拓荒初體驗 | 完成一次 BBTI 測驗，看到自己的聚落身份 | 2 |
| Q2 | 號召旅人 | 複製／分享自己的測驗結果連結 | 1 |
| Q3 | 拜訪據點 | 到現場指定攤位報到（每個攤位各 1 點，可累計多個） | 1／攤位 |
| Q4 | 聚落講堂 | 完整聽完一場議程分享，並填寫回饋表單（每場議程各 1 點，可累計多個） | 1 |
| Q5 | 結識同好 | 與另一位旅人交換 BBTI 測驗結果、互相看對方的類型 | 1 |
| Q6 | 聚落公告 | 在社群媒體發文並標註活動指定 hashtag | 1 |
| Q7 | 拓荒回饋 | 填寫活動意見回饋表單 | 1 |
| Q8 | 聚落制霸 | 完成以上 Q1–Q7 全部任務（額外加成，不是重複給分） | 2（加成） |

單場活動理論最高點數：2(Q1) + 1(Q2) + 視攤位數(Q3) + 1(Q4) + 1(Q5) + 1(Q6) + 1(Q7) + 2(Q8 加成)。Q3 的攤位數量與 Q4 的議程場次數量，需依實際活動議程表填入。

## 4. 任務完成認定方式

**已確認**：現場任務分兩種認定機制：

- **Q4／Q5／Q6（他人登記型）**：每位旅人登入後都有一組專屬的「聚落通行證」，包含個人 QR Code 與一組短代號。登記任務完成時，由工作人員（或 Q5 的對象旅人）**掃描該 QR Code，或在掃描不方便時改用手動輸入代號**登記，兩種方式擇一即可，登記後系統即記錄該任務完成。
- **Q3（自助掃描型）**：反過來由旅人主動掃描攤位的 QR Code，不需要工作人員操作，見下表 Q3 說明。

### 4.1 個人通行證頁面

**已確認**：需要一個新畫面「我的通行證」，旅人登入後可以看到自己的 QR Code 與代號。代號是一個新欄位，顯示為十碼數字。這組代號須為系統隨機產生，不能是流水號／遞增 ID 這類可預測的值——十碼數字本身提供足夠大的空間（最多 100 億種組合），但前提是隨機產生，否則位數再多也防不了用遞增方式猜測。

| 欄位 | 說明 |
|---|---|
| QR Code | 依代號即時產生的 QR 圖像，供工作人員或其他旅人掃描 |
| 代號 | 十碼數字，隨機產生、不可重複，作為掃描失敗時的手動輸入備援 |
| 分享按鈕 | **已確認**：頁面需提供分享按鈕，讓旅人可將此頁面分享到 Facebook 與 Threads。**已確認與 Q2 號召旅人任務的分享機制各自獨立、不共用**：Q2 分享的是測驗結果連結，此按鈕分享的是通行證相關內容，兩者是不同的功能，點擊此按鈕不會觸發 Q2 任務判定。分享出去的連結內容不可直接帶出代號本身（代號屬於現場登記備援憑證，外洩有被冒用登記任務的風險），實際分享連結導向哪一頁與文案／圖片素材仍待確認，見 §5 待確認事項 |

| 任務 | 認定方式 |
|---|---|
| Q1 拓荒初體驗、Q2 號召旅人 | 系統自動判定：使用者帳號底下有 `quiz_attempts` 紀錄即完成 Q1；點擊分享連結按鈕即完成 Q2 |
| Q3 拜訪據點 | **已確認，機制與其他現場任務不同**：每個攤位各自有一個攤位專屬 QR Code，旅人用自己的手機掃描該攤位的 QR Code 即可獲得點數，不需要工作人員操作。同一攤位對同一旅人只能取得一次點數，已掃過的攤位不可重複取得 |
| Q4 聚落講堂 | 講堂工作人員掃描旅人的個人 QR Code，或手動輸入其代號，登記完成；仍需搭配填寫回饋表單 |
| Q5 結識同好 | 雙方互相掃描對方的個人 QR Code，或手動輸入對方代號，互相登記完成 |
| Q6 聚落公告 | 旅人自行提交貼文截圖，工作人員審核後手動輸入其代號登記完成（無現場掃描場景，走手動輸入） |
| Q7 拓荒回饋 | 系統自動判定：回饋表單送出紀錄 |
| Q8 聚落制霸 | 系統依 Q1–Q7 完成狀態自動判定 |

### 4.2 任務進度頁面

**已確認**：兌換動線需要一個畫面，讓旅人登入後能看到自己已完成的所有任務清單、目前累積點數、以及對應解鎖的獎勵層級。旅人到兌換現場時，出示這個畫面（或由工作人員掃描其通行證 QR Code 帶出同樣的畫面）作為兌換依據。實際的兌換地點、獎品交付方式仍待第 5 節確認。

## 5. 待確認事項

以下需要活動主辦端／你確認，才能把這份規格書定案：

1. **攤位與議程的實際數量與名單**：Q3、Q4 的點數上限依此決定，目前規劃是每個攤位/場次各 1 點。
2. **獎品內容與採購**：第 3 節的獎勵層級目前是佔位文字，需要實際獎品清單。
3. **兌換動線（部分確認）**：旅人憑「任務進度頁面」（見 §4.2）兌換，已確認用手機畫面而非紙本章卡。仍待確認：實際兌換地點在哪裡、獎品數量是否有限、售罄後怎麼處理。
4. **是否需要防止重複兌換／灌水**：例如 Q3 攤位點數會不會被重複登記，是否需要類似 `docs/mbti-quiz-planning.md` §6 的 IP 節流的防濫用機制。
5. **登記介面的存取權限**：「掃描或輸入代號登記任務」這個功能，只開放給工作人員的帳號／裝置使用，還是旅人自己也連得到——如果旅人自己也能存取，等於能自己幫自己登記，任務認定會失去意義。
6. **通行證頁面分享按鈕的細節**（已確認與 Q2 分享機制各自獨立，不共用、不計入 Q2 點數）：分享到 Facebook／Threads 時要帶什麼內容——由於代號不可外洩，分享出去的連結不能是通行證頁面本身，需另外設計導向頁（例如活動首頁／通用宣傳頁）；文案與縮圖素材由誰準備，仍待確認。
