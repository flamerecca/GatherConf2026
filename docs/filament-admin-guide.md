# MBTI 測驗 — Filament 後台管理文件

本文件說明如何在 Filament 後台管理「性格測驗」的內容，對象為負責維護題目與類型文案的內容／行銷人員，不需要工程背景。技術實作細節請參考 `docs/mbti-quiz-planning.md`。

---

## 1. 登入後台

網址：`/admin/login`

登入後，左側選單會看到兩個與測驗相關的管理項目：

- **性格類型**（Personality Types）
- **測驗題目**（Quiz Questions）

「會員」群組下還有「漂流瓶」、「NPC 角色」與「授權碼」，用法見第 6、7、8 節。

---

## 2. 性格類型管理（Personality Types）

對應 16 種性格類型（如 `NSHG`、`VMAD`）的文案內容，測驗結果頁會依使用者算出的四字代碼，顯示這裡填寫的內容。

| 欄位 | 說明 | 備註 |
|---|---|---|
| 代碼（code） | 四字類型代碼，如 `NSHG` | 系統初始化時已建立好全部 16 筆，**不需要新增**，也不要修改代碼本身，否則測驗結果會找不到對應類型 |
| 名稱（name） | 類型的暱稱，如「建築師」 | 可自由編輯 |
| 摘要（summary） | 一句話摘要，會顯示在結果頁最上方 | 建議 20-40 字內 |
| 完整說明（description） | 詳細描述文字 | 支援較長篇幅 |
| 優勢（strengths） | 條列式優點 | 每行一項 |
| 待成長（weaknesses） | 條列式待成長項目 | 每行一項，可留空 |
| 職涯發展建議（career_advice） | 適合的職位與發展方向，顯示在結果頁的「職涯發展建議」 | 一小段文字，可留空，留空時結果頁不顯示這個區塊 |
| 強化自己的方向（growth_directions） | 條列式的強化建議，顯示在結果頁的「強化自己的方向」 | 每行一項，建議 3 項，可留空，留空時結果頁不顯示這個區塊 |

職涯發展建議與強化自己的方向，16 種類型都已預先填好內容，可以直接在後台修改，重新部署不會覆蓋已修改的內容。

**操作方式：** 進入「性格類型」列表，點選任一筆進行編輯、儲存即可。**沒有刪除或新增功能**——16 種類型是固定的，只能編輯內容文字。

## 3. 測驗題目管理（Quiz Questions）

測驗實際出的題目都在這裡管理，可以新增、編輯、下架、調整順序。

| 欄位 | 說明 | 備註 |
|---|---|---|
| 所屬維度（axis） | 這題是在測哪一組對立維度：`SV`、`NM`、`HA`、`GD` | 見下方對照表 |
| 傾向極性（positive_pole） | 使用者選「同意」時，代表偏向哪一個字母 | **必須跟所屬維度配對**，見下方對照表 |
| 題目文字（text） | 使用者實際看到的題目敘述 | |
| 顯示順序（order） | 數字越小越早出現 | 用來控制題目出現的先後順序 |
| 是否啟用（is_active） | 關閉後這題不會出現在測驗中 | **要拿掉一題，用「關閉」而不是刪除**，避免影響已作答者的歷史紀錄 |

### 維度與傾向極性對照表

新增或編輯題目時，「傾向極性」只能填下表中對應的其中一個，**不要填錯邊**，否則這題的分數會算到錯誤的性格傾向上：

| 所屬維度 | 可填的傾向極性 |
|---|---|
| NM | N（新奇開拓）或 M（穩固成熟） |
| SV | S（系統）或 V（視覺） |
| HA | H（親手介入）或 A（自動化生成） |
| GD | G（熱情採集）或 D（深入探索） |

> 範例：新增一題「我喜歡動手調整系統設定，而不是靠視覺化介面操作」，這題是在測 SV 維度，同意代表偏向系統，所以「所屬維度」填 `SV`、「傾向極性」填 `S`。

### 常見操作

- **新增一題**：點「新增」，依序填寫上表欄位，記得設定「顯示順序」讓題目排在合理位置。
- **暫時不用某一題**：把「是否啟用」關閉即可，不用刪除。
- **調整題目出現順序**：在題目列表直接拖曳排序，或修改「顯示順序」數字，數字小的先出現。
- **建議每個維度至少維持一定題數**，初始資料每維度 10 題，共 40 題，兩極各 5 題。若某一維度啟用中的題目太少，測驗結果的準確度會下降。

### 抽題規則

每次測驗不是出全部題目，而是從啟用中的題庫隨機抽出 12 題：

- 四個維度各抽 3 題，所以每個維度的滿分都是 6，結果頁的長條比例才公平。
- 每個維度至少要有 3 題啟用中的題目。不足時會從其他維度補題，那次測驗的各維度滿分就會不一樣。
- 啟用中的題目總數不到 12 題時，會全部出題。
- 同一個人重新整理頁面，題目不會變，送出後再開始測驗才會重新抽題。
- 被抽中的題目仍照「顯示順序」排列。

## 4. 目前後台**不包含**的功能

以下項目依規劃書屬於 MVP 階段刻意不做，如需要要另外提出需求：

- 逐題作答數據的檢視（誰在哪一題選了什麼）
- 測驗結果（quiz_attempts）的後台列表／統計檢視
- 匯入／匯出題目

## 5. 給工程實作者的提醒

「傾向極性」欄位在資料庫層級是涵蓋全部 8 個字母的 enum，沒有強制跟「所屬維度」的合法組合綁定。實作 `QuizQuestionResource` 表單時，務必用 `Get $get` 讓「傾向極性」的選項依「所屬維度」動態限制為對應的兩個值，避免內容人員在後台填出不合法組合（例如維度選 `SV`、極性卻選了 `H`），否則計分邏輯會產生錯誤但不會報錯。

## 6. 漂流瓶管理與系統漂流瓶

進入「會員」群組的「漂流瓶」，可以查看所有漂流瓶，依狀態、待處理檢舉與日期篩選，並下架或還原瓶子與回覆。

### 發送系統漂流瓶

在漂流瓶列表右上角按「系統漂流瓶」：

| 欄位 | 說明 |
|---|---|
| 發送角色 | 選擇 NPC 角色，不選則以「系統」發送，NPC 角色見第 7 節 |
| 內容 | 瓶子內容，最多 300 字 |

- 瓶子會直接送給一位隨機的符合資格會員：帳號啟用、email 已驗證，且持有未開啟的瓶子未滿 5 個。
- 收件者會收到「收到漂流瓶」email。
- 沒有符合資格的會員時，不會留下瓶子，畫面會顯示警告。
- 系統漂流瓶是指定送給某位會員的，不會被 24 小時未開啟的排程退回海裡，也不會被其他會員撿走。
- 收件者可以回覆，回覆內容會顯示在該瓶子的詳情頁。以「系統」發送時沒有寄件會員，所以不會寄回覆通知 email。
- 列表與詳情的寄件者欄位，以「系統」發送的瓶子會顯示「系統」，以 NPC 發送的瓶子會顯示綁定會員，並另外顯示「NPC 角色」。

## 7. NPC 角色管理

進入「會員」群組的「NPC 角色」，可以新增、編輯與刪除角色。

| 欄位 | 說明 |
|---|---|
| 角色名稱 | 如「森林長老」，不可重複，收件者開啟瓶子時會看到「來自 森林長老 的瓶子」 |
| 綁定會員 | 一位真實的會員帳號，以該角色發送系統漂流瓶時，這位會員就是寄件者 |

- 建議為每個 NPC 角色準備專用的會員帳號，email 要是營運人員收得到的信箱，因為收件者的回覆通知會寄到這個信箱。
- 綁定的會員本身不會收到自己發出的瓶子。
- 列表會顯示每個角色已發送的瓶數。

## 8. 授權碼管理

進入「會員」群組的「授權碼」，可以新增與編輯授權碼，會員在 `/member/tasks` 輸入後換取胡蘿蔔，會員端的行為見 `docs/member-tasks-page.md` 第 5 節。

| 欄位 | 說明 |
|---|---|
| 名稱 | 給管理員辨識用，會員看不到 |
| 授權碼 | 留空會自動產生 8 碼，也可以自訂，如 `gather-2026`，儲存時會轉成大寫並移除符號，變成 `GATHER2026` |
| 獎勵胡蘿蔔數量 | 兌換一次獲得的數量 |
| 可兌換次數上限 | 全部會員合計最多可兌換幾次，留空代表不限 |
| 啟用 | 關閉後無法兌換 |
| 開始時間、結束時間 | 可兌換的期間，留空代表不限 |

- 每位會員同一組授權碼只能兌換一次。
- 列表會顯示每組授權碼已兌換的次數，有上限的顯示為「已兌換 / 上限」，授權碼欄位可以直接複製。
- 授權碼不可與現場任務的短碼重複，重複時儲存會失敗。
- 現場任務的短碼在「胡蘿蔔任務」列表與詳情頁可以看到，會員輸入短碼等於完成該任務，不需要另外設定。
- 每筆兌換都會記在「胡蘿蔔交易」，原因為 `code`，可以用原因篩選。
- 目前沒有撤銷單筆授權碼兌換的功能，需要時請用手動調整胡蘿蔔處理。
