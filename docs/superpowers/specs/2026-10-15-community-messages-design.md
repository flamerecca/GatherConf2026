# 會員發訊息給合作社群設計規格

日期：2026-10-15
狀態：待審閱

## 1. 背景與目標

合作社群目前只是 `config/communities.php` 裡的靜態資料，只有名稱、網址與簡介，沒有帳號與聯絡信箱。會員想詢問合作社群或表達合作意願時，沒有管道。

本規格讓會員在合作社群頁選擇一個社群並送出訊息，訊息進入主辦方的後台收件匣，由管理員轉交給該社群。

成功條件：

1. 已登入且已驗證的會員可以對任一合作社群送出一則訊息。
2. 訊息出現在後台的「社群訊息」列表，管理員看得到寄件會員、社群與內容。
3. 管理員可以標記處理狀態並留下備註，會員可以看到自己訊息的處理狀態。
4. 同一位會員不能短時間內大量送出。
5. 合作社群不需要提供任何聯絡資料，也不需要有帳號。

## 2. 已確認的決策

| 項目 | 決策 |
| :---- | :---- |
| 發送者 | 會員，不是主辦方。 |
| 收件方式 | 主辦方後台收件匣轉交，不記錄社群信箱。 |
| 入口 | 合作社群頁每張卡片的「聯絡這個社群」，需登入且已驗證。 |
| 內容 | 主旨最多 100 字，內文最多 1000 字，純文字，不限制網址。 |
| 社群識別 | `config/communities.php` 每筆新增固定的 `slug`，訊息同時存下當時的社群名稱。 |
| 限額 | 每位會員滾動 24 小時內最多 5 則，另有每分鐘 5 次的請求限流。 |
| 回覆方式 | 管理員用現有信箱回覆會員，網站內不做對話串。 |
| 通知 | 送出後寄確認信給會員，不含內文，不另外通知管理員。 |
| 行為準則 | 送出前勾選同意，不做事前審核。 |
| 實作階段 | 單一階段。 |

## 3. 不在範圍內

- 合作社群的帳號、信箱與收件匣。
- 網站內的對話串與會員回覆。
- 附件與圖片。
- 關鍵字或機器審核。
- 通知管理員的 Email 或推播。
- 公開顯示會員訊息。
- 由社群主動發訊息給會員。

## 4. 規則

### 4.1 入口與登入

- 合作社群頁每張卡片新增連結「聯絡這個社群」，指向該社群的寫訊息頁，繁體中文與英文各一組路由。
- 寫訊息頁需要登入且已驗證 Email，訪客導向登入頁，登入後回到原頁，沿用既有的 intended 機制。
- 路徑中的 `slug` 不存在時回應 404。
- 合作社群頁本身維持公開，未登入者也看得到連結。

### 4.2 送出訊息

- 欄位：主旨與內文，都必填，去除前後空白後主旨 1 到 100 字，內文 1 到 1000 字，純文字。
- 必須勾選「我已閱讀並同意行為準則」，並提供行為準則頁面連結。
- 每位會員滾動 24 小時內最多送出 5 則，超過回傳驗證錯誤。另有請求限流，每位會員每分鐘 5 次。
- 只有啟用且已驗證的會員可以送出。
- 送出成功後導向「我寄給社群的訊息」並顯示成功訊息，狀態為待處理。
- 寄確認信給會員，不含主旨與內文，只說明已送出給哪個社群與如何查看狀態，寄信失敗只記錄，不影響主流程。確認信語系固定為繁體中文。

### 4.3 處理狀態

| 狀態 | 意義 |
| :---- | :---- |
| `pending` | 待處理，新訊息的預設值。 |
| `forwarded` | 已轉交，管理員已經把訊息交給社群。 |
| `closed` | 已結案，不需再處理。 |

- 管理員可以在三種狀態之間切換，狀態變更記錄處理人與時間。
- 管理員備註只有管理員看得到，會員看不到。
- 會員只看得到狀態，看不到備註。

### 4.4 會員端

- 路徑 `/member/community-messages`，列出自己送出的訊息，顯示社群名稱、主旨、送出時間與狀態，不顯示內文。
- 只有本人看得到自己的訊息，其他會員與訪客無法存取。
- 會員中心加入連結。

### 4.5 後台

- 新增「社群訊息」資源，導覽群組「會員」，導覽標籤顯示待處理數量。
- 列表欄位：寄件會員、社群、主旨、狀態、送出時間。搜尋：主旨、內文、寄件會員姓名與 Email。篩選：狀態、社群、日期。
- 檢視頁顯示寄件會員的姓名、Email、所屬組織、社群、主旨、內文、狀態、處理人、備註。
- 動作：標記已轉交、標記已結案、重新開啟為待處理，以及編輯備註。
- 後台不提供新增與編輯主旨或內文，也不提供刪除。

### 4.6 隱私

- 訊息只有寄件會員與管理員看得到。
- 管理員可以看到寄件會員的 Email，目的是回覆會員。
- 會員被刪除時，其送出的訊息一併刪除。
- 訊息內容不出現在確認信與任何通知中。

## 5. 資料層

| 資料表 | 欄位 |
| :---- | :---- |
| `community_messages` | `id` uuid、`member_id` 外鍵 cascade、`community_slug`、`community_name`、`subject`、`body`、`status`、`admin_note` 可為空、`handled_by` 可為空、`handled_at` 可為空、時間戳記。 |

- 沿用 UUIDv7 主鍵與 `foreignUuid` 外鍵，新增 migration，不修改既有 migration。
- 索引：`(status, created_at)` 與 `(member_id, created_at)`。
- `community_name` 儲存送出當下社群的繁體中文名稱，社群改名後舊訊息仍可辨識。
- 新增模型 `CommunityMessage` 與 factory，以 `#[Fillable]` Attribute 設定。
- `config/communities.php` 每筆新增 `slug`，小寫英文數字與連字號，全清單唯一，並更新檔頭型別註解。
- 新增 `Communities` 取得社群的輔助類別，依 `slug` 找出設定，放在 `app/Models/`，不新增 `app/` 底下的基底資料夾。

## 6. 前台

沿用既有的雙語路由、`member.locale`、`member.active`、`member.verified`，路徑放在 `/member` 下，使 `robots.txt` 既有的前綴涵蓋。

| 名稱 | 方法與路徑 | 說明 |
| :---- | :---- | :---- |
| `member.community-message.create` | GET `/member/communities/{slug}/message` | 寫訊息頁。 |
| `member.community-message.store` | POST `/member/communities/{slug}/message` | 送出，限流每分鐘 5 次。 |
| `member.community-messages` | GET `/member/community-messages` | 我寄給社群的訊息。 |

- 所有新頁面加 `noindex`，繁體中文與英文各一組文案，文案放 `lang/{zh_TW,en}/community-messages.php`。
- 合作社群卡片元件 `x-community-card` 在合作社群頁顯示連結，首頁區塊維持原樣。

## 7. 前置條件與風險

| 項目 | 說明 |
| :---- | :---- |
| 管理員沒有收到通知 | 訊息只出現在後台，沒人看就沒人回。以導覽標籤顯示待處理數量降低風險，之後可再加管理員通知。 |
| 轉交是人工作業 | 管理員要自己把訊息轉給社群，主辦方需要負責回覆會員。 |
| 垃圾訊息 | 只靠登入、驗證、每日 5 則限額與行為準則勾選，沒有內容審核。 |
| 會員的 Email 暴露給管理員 | 屬於回覆所需，已在登入頁面以外的隱私說明處提及即可。 |
| slug 一旦公開就不能改 | 改 slug 會讓舊連結 404，舊訊息仍保留社群名稱。 |

## 8. 測試

全部使用 PHPUnit feature 測試，並以 factory 建立資料。

- 設定：每個社群都有 `slug`，格式正確且全清單唯一。
- 寫訊息頁：登入且已驗證的會員看得到表單，標題顯示社群名稱，中英文各自正確。
- 寫訊息頁：訪客導向登入並在登入後回到原頁，未驗證會員導向驗證頁，停用會員無法使用。
- 寫訊息頁：不存在的 `slug` 回應 404。
- 送出：成功時建立 `pending` 訊息並存下社群名稱，主旨與內文被去除前後空白。
- 送出：主旨與內文必填、長度上限、未勾選行為準則被拒絕。
- 送出：24 小時內第 6 則被拒絕，24 小時前的訊息不計入，請求限流回應 429。
- 送出：寄出一封確認信，不含主旨與內文，寄信失敗不影響送出。
- 會員端：只列出自己的訊息，顯示狀態，不顯示內文與備註，訪客導向登入。
- 後台：列表顯示、搜尋與篩選、檢視頁顯示寄件會員資料。
- 後台：標記已轉交、已結案、重新開啟會記錄處理人與時間，備註可編輯，主旨與內文不可編輯，沒有新增與刪除。
- 後台：導覽標籤顯示待處理數量。
- 會員被刪除：其訊息一併刪除。
- 合作社群頁：每張卡片都有聯絡連結，首頁區塊沒有。

## 9. 實作階段

單一階段：`slug` 設定、migration 與模型、前台頁面、確認信、後台資源、合作社群頁連結與測試。
