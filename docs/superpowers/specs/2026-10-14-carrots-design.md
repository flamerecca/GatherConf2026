# 會員胡蘿蔔點數系統設計規格

日期：2026-10-14
狀態：待審閱

## 1. 背景與目標

年會網站已有會員、好友、短信與人格測驗。本規格加入以胡蘿蔔呈現的會員點數，會員完成任務就能獲得胡蘿蔔，並可以在任務列表頁看到哪些行為會被獎勵。

胡蘿蔔最終可在年會現場兌換獎品。兌換屬於階段二，本規格只涵蓋階段一：帳本、賺取、顯示與後台管理。

成功條件：

1. 會員完成站上既有行為時，自動獲得一次性的胡蘿蔔。
2. 會員掃描現場任務的 QR Code，登入後獲得該任務的胡蘿蔔，每人每任務只能一次。
3. 管理員可以在後台建立現場任務並手動調整會員的胡蘿蔔，每筆調整必須留下原因。
4. 會員可以在任務列表頁看到所有會被獎勵的行為、獎勵數量與自己是否已完成。
5. 同一件事不論重複觸發幾次，都只發放一次。
6. 胡蘿蔔餘額永遠不為負，且可由帳本明細加總驗證。

## 2. 已確認的決策

| 項目 | 決策 |
| :---- | :---- |
| 賺取來源 | 站上既有行為、年會現場任務、後台手動發放。 |
| 現場任務證明方式 | 掃描任務專屬 QR Code。 |
| 用途 | 可兌換獎品，兌換為階段二。 |
| 兌換方式 | 會員產生短時效碼，工作人員掃描核銷，階段二處理。 |
| 既有會員補發 | 不補發，只計算上線後的新行為。 |
| 工作人員 | 沿用後台管理員白名單，不另建角色。 |
| 站上行為獎勵數量 | 放在組態檔，不放後台。 |
| 實作階段 | 階段一為帳本、賺取、任務列表頁與後台，階段二為獎品與兌換。 |

## 3. 不在範圍內

- 獎品、庫存、兌換碼與核銷，屬階段二。
- 排行榜、每日簽到、點數過期。
- 會員之間轉贈胡蘿蔔。
- 補發既有會員已完成的行為。
- 工作人員專用角色與行動端掃描介面。

## 4. 規則

### 4.1 帳本

- 每次胡蘿蔔增減都寫入一筆 `carrot_transactions`，只新增，不修改也不刪除。
- `amount` 為非零整數，正數為獲得，負數為扣除，階段二的兌換使用負數。
- `dedupe_key` 有唯一索引。同一個 `dedupe_key` 再次寫入時不報錯，也不發放，回傳「已發放過」。
- 會員餘額 `members.carrots` 是快取，與帳本在同一個資料庫交易內更新，餘額與帳本加總必須一致。
- 扣除後餘額會小於 0 的交易一律拒絕，不寫入帳本。
- 每筆交易記錄原因代碼 `reason`、選填的說明 `note`，以及來源任務 `task_id`，任務與手動調整以外為空。

### 4.2 站上既有行為

由系統在行為成功後自動發放，數量定義在 `config/carrots.php`。

| 行為代碼 | 說明 | `dedupe_key` |
| :---- | :---- | :---- |
| `verify_email` | 完成 Email 驗證，包含點擊登入連結與重設密碼。 | `verify_email:{member}` |
| `set_password` | 第一次設定密碼。 | `set_password:{member}` |
| `complete_quiz` | 第一次完成人格測驗。 | `complete_quiz:{member}` |
| `first_friend` | 第一位好友關係成立，雙方各得一次。 | `first_friend:{member}` |
| `first_message` | 第一次成功傳出短信。 | `first_message:{member}` |

- 行為本身成功才發放，行為失敗或被限流時不發放。
- 發放失敗不能讓原行為失敗，錯誤記錄後略過。
- 上線前已完成的行為不補發，因此只有上線後才首次發生的行為會獲得獎勵。

### 4.3 現場任務

- 管理員在後台建立任務，欄位為名稱、說明、獎勵數量、啟用開關、選填的開始與結束時間。
- 每個任務有隨機且不可猜測的 `code`，用來組成 QR Code 網址。
- 路徑 `/member/tasks/{code}`，需要登入且已驗證 Email。未登入者導向登入頁，登入後回到原網址，沿用既有的 intended 機制。
- 任務未啟用、尚未開始或已結束時，不發放，顯示對應提示。
- 每位會員每個任務只能獲得一次，`dedupe_key` 為 `task:{task}:{member}`，重複掃描顯示「已完成過」。
- 掃描端點限流，每位會員每分鐘 20 次。
- `code` 不顯示在任務列表頁與任何前台頁面，只顯示在後台，避免會員不到現場就能完成任務。

### 4.4 後台手動調整

- 管理員在會員檢視頁可以加減胡蘿蔔，必填整數與原因。
- 不可扣到負數，`dedupe_key` 為隨機值，每次調整都是獨立一筆。
- 調整者的使用者 id 記錄在 `note` 以外的 `created_by`，供稽核。

### 4.5 任務列表頁

目的是讓會員知道哪些行為會被獎勵，以及自己的進度。

- 路徑 `/member/tasks`，雙語路由，需要登入且已驗證 Email。
- 頁面分兩區：
  - 「站上任務」：列出 4.2 節的全部行為，顯示名稱、一行說明、獎勵數量與狀態。
  - 「年會現場任務」：列出目前啟用且在有效期間內的任務，顯示名稱、說明、獎勵數量與狀態。
- 狀態只有「已完成」與「未完成」兩種，由帳本的 `dedupe_key` 判斷，不另存狀態。
- 頁首顯示目前胡蘿蔔總數。
- 現場任務不顯示 `code`、也不提供點擊完成，只提示「到年會現場掃描任務 QR Code」。
- 尚未開始或已結束的任務不顯示在列表中。
- 會員中心加入前往任務列表頁的連結，以及目前胡蘿蔔數量。
- 頁面加 `noindex`，並列入 `robots.txt` 的會員路徑禁止清單。

## 5. 資料層

| 資料表 | 欄位 |
| :---- | :---- |
| `carrot_transactions` | `id` uuid、`member_id` 外鍵、`amount`、`reason`、`note` 可為空、`task_id` 可為空、`created_by` 可為空、`dedupe_key` 唯一、時間戳記。 |
| `carrot_tasks` | `id` uuid、`name`、`description`、`reward`、`code` 唯一、`is_active`、`starts_at` 與 `ends_at` 可為空、時間戳記。 |
| `members` | 新增 `carrots` 無號整數，預設 0。 |

- 沿用 UUIDv7 主鍵與 `foreignUuid` 外鍵。
- 新增 migration，不修改既有 migration。
- 新增模型 `CarrotTransaction`、`CarrotTask`，並提供 factory。
- 新增服務類別 `CarrotLedger`，唯一的寫入入口，提供 `award`、`adjust`、`balance`。

## 6. 前台

| 名稱 | 方法與路徑 | 說明 |
| :---- | :---- | :---- |
| `member.tasks` | GET `/member/tasks` | 任務列表頁。 |
| `member.tasks.complete` | GET `/member/tasks/{code}` | 掃描現場任務 QR Code 後發放，顯示結果頁。 |

- 沿用 `member.locale`、`member.active`、`member.verified` 中介層。
- 結果頁依狀態顯示：已獲得、已完成過、任務未開放。
- 繁體中文與英文各一組文案。

## 7. 後台

- 新增「胡蘿蔔任務」資源：列表、建立、編輯，檢視頁顯示可列印的 QR Code 與網址。
- 會員檢視頁新增胡蘿蔔餘額、調整動作與唯讀的交易明細。
- 新增唯讀的「胡蘿蔔明細」列表，可依會員、原因篩選。
- 導覽群組沿用「會員」。

## 8. 前置條件與風險

| 項目 | 說明 |
| :---- | :---- |
| QR Code 外流 | 任務 QR Code 一旦被拍照傳出去，不在現場也能完成。第一版接受此風險，可由結束時間與停用開關降低影響。 |
| 站上行為被刷 | 每個行為限一次，且依賴既有的註冊與信箱驗證限流，大量建立帳號的風險由既有機制控制。 |
| 餘額與帳本不一致 | 交易內同時更新，並提供測試驗證加總一致。 |
| 不補發 | 現有會員的既有成果不會有胡蘿蔔，需對外說明。 |
| 掃碼流程 | 會員未登入時掃碼，需先登入，登入連結的瀏覽器需與掃碼瀏覽器相同才能回到任務頁。 |

## 9. 測試

全部使用 PHPUnit feature 測試，並以 factory 建立資料。

- 帳本：發放寫入明細並更新餘額，重複 `dedupe_key` 不重複發放也不報錯。
- 帳本：扣除會讓餘額為負時被拒絕，帳本與餘額都不變。
- 帳本：餘額等於明細加總。
- 站上行為：五種行為各發放一次，失敗與重複時不發放，發放失敗不影響原行為。
- 現場任務：登入後掃描發放，重複掃描不重複發放，未登入導向登入並回到任務頁。
- 現場任務：未啟用、未開始、已結束都不發放。
- 現場任務：未驗證 Email 的會員被導向，掃描限流後回應 429，錯誤的 `code` 回應 404。
- 後台：建立任務、調整需要原因、不可扣到負數、明細唯讀。
- 任務列表頁：列出站上行為與有效的現場任務，不顯示 `code`，已完成與未完成狀態正確。
- 任務列表頁：未啟用、未開始、已結束的任務不顯示，訪客被導向，中英文各自正確。
- 會員中心：顯示胡蘿蔔數量與任務列表連結。

## 10. 實作階段

階段一：migration、模型與 `CarrotLedger`、站上行為發放、現場任務、任務列表頁、會員中心、後台資源、文案與測試。

階段二另寫規格：獎品、庫存、兌換碼與工作人員核銷。
