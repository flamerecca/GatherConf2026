# 會員漂流瓶設計規格

日期：2026-10-15
狀態：待審閱

## 1. 背景與目標

年會參加者彼此多半不認識。本規格加入漂流瓶：會員可以丟出一則匿名短訊給陌生的會員，對方可以匿名回覆一次。內容必須符合行為準則，採取先送後審並提供檢舉。

成功條件：

1. 會員可以丟出一個瓶子，系統立即隨機指派給一位符合資格的陌生會員。
2. 會員可以從「海」裡撿一個瓶子，海裡是沒被指派或被釋放的瓶子。
3. 收件人可以匿名回覆一次，寄件者看得到回覆，之後雙方都不能再傳。
4. 雙方都不會得知對方的身分，只有管理員看得到。
5. 收件人可以一鍵檢舉瓶子，寄件者可以檢舉回覆，被檢舉的內容立即對對方隱藏，管理員在後台處理。
6. 不是啟用且已驗證的會員、好友與封鎖對象，不會收到彼此的瓶子。

## 2. 已確認的決策

| 項目 | 決策 |
| :---- | :---- |
| 內容審核 | 先送後審，加上收件人檢舉。 |
| 收件後互動 | 匿名回覆一次，可以檢舉或忽略。 |
| 投遞方式 | 系統隨機指派，也可以自己撿。 |
| 實作階段 | 單一階段。 |

## 3. 不在範圍內

- 揭露身分、轉為好友、多輪對話。
- 關鍵字或機器審核。
- 圖片、檔案、連結預覽。
- 與胡蘿蔔點數連動。
- 瓶子的轉丟、收藏與刪除。
- 即時更新，需重新整理頁面。

## 4. 規則

### 4.1 丟出瓶子

- 欄位：內容，必填，去除前後空白後 1 到 300 字，純文字。
- 必須勾選「我已閱讀並同意行為準則」，並提供行為準則頁面連結。
- 內容不可含網址與 Email，以降低垃圾訊息與個資外洩，違反時回傳驗證錯誤。本條為本規格自行加入，可在審閱時調整。
- 每位會員滾動 24 小時內最多丟出 3 個，超過回傳驗證錯誤。另有請求限流，每位會員每分鐘 10 次。
- 只有啟用且已驗證的會員可以丟出。
- 丟出後立即嘗試指派，見 4.2。

### 4.2 指派

符合資格的收件人必須全部成立：

- 啟用且已驗證 Email。
- 不是寄件者本人。
- 與寄件者沒有好友關係，包含待確認的邀請。
- 與寄件者沒有封鎖關係，雙向都算。
- 不在這個瓶子的 `released_recipient_ids` 內。
- 目前持有的未開啟瓶子少於 5 個。

規則：

- 從符合資格者中隨機挑一位，建立 `recipient_id` 與 `assigned_at`。
- 找不到符合資格者時，瓶子留在海裡，`recipient_id` 為空，仍算丟出成功。
- 指派以條件式更新完成，`recipient_id` 為空才能被指派，避免兩個請求同時搶到同一個瓶子。

### 4.3 撿取

- 會員按「撿一個瓶子」，從海裡符合資格的瓶子隨機取一個，資格同 4.2，收件人視為撿取者。
- 目前持有的未開啟瓶子已達 5 個時不能撿，顯示提示。
- 每位會員每天最多撿 10 次，另有請求限流每分鐘 10 次。
- 海裡沒有符合的瓶子時顯示「海裡暫時沒有瓶子」，不算一次嘗試。
- 撿取同樣以條件式更新，只有一位會員能拿到同一個瓶子。

### 4.4 釋放

- 已指派但 24 小時內沒有被開啟的瓶子，由排程每小時釋放回海裡。
- 釋放時清空 `recipient_id` 與 `assigned_at`，並把原收件人加入 `released_recipient_ids`，同一個人不會再被指派或撿到同一個瓶子。
- 已開啟、已回覆與已下架的瓶子不釋放。

### 4.5 開啟與回覆

- 只有收件人可以開啟，進入瓶子頁面時寫入 `opened_at`。
- 收件人在開啟後可以回覆一次，回覆 1 到 300 字，規則同 4.1，不需要再勾選行為準則。
- 回覆後瓶子狀態為已回覆，雙方都不能再傳訊息。
- 寄件者在「我丟出的瓶子」看到回覆，回覆者同樣匿名。
- 瓶子被下架後不能回覆。

### 4.6 檢舉與下架

- 收件人可以檢舉瓶子，寄件者可以檢舉回覆。
- 檢舉成立時立即對對方隱藏該內容，被檢舉的一方不會被通知。
  - 瓶子被檢舉：寫入 `removed_at`，收件人不再看得到，寄件者看到「這個瓶子已被下架」。
  - 回覆被檢舉：寫入 `reply_removed_at`，寄件者不再看得到回覆內容。
- 一次檢舉只記錄一筆，同一位會員對同一個目標重複檢舉不會產生第二筆。
- 檢舉可附選填的原因，最多 200 字。
- 收件人也可以選擇「忽略」，不檢舉，瓶子保持已開啟，不需動作。

### 4.7 後台處理

- 管理員可以看到所有瓶子，包含寄件者、收件人、內容、回覆與狀態。
- 檢舉有三種處理結果：
  - 確認違規：保持下架，記錄處理人與時間。
  - 駁回：還原該內容並記錄處理人與時間。
  - 停用寄件者：沿用既有的會員停用動作，由管理員在會員頁執行。
- 管理員也可以不經檢舉直接下架或還原任何瓶子與回覆。
- 後台不提供編輯內容與以會員身分回覆。

### 4.8 通知

- 瓶子被指派或撿取時不通知，撿取者自己就在頁面上。
- 被指派時寄提醒信給收件人，不含內文，同一位收件人 15 分鐘內只寄一次。
- 回覆後寄提醒信給寄件者，不含內文。
- 寄信失敗只記錄，不影響主流程。提醒信語系固定為繁體中文，與既有訊息提醒信一致。

### 4.9 隱私

- 所有前台頁面、通知、網址都不含對方的姓名、Email、組織或會員編號。
- 瓶子網址使用瓶子的 UUID，非參與者回應 404。
- 會員被刪除時，其作為寄件者的瓶子一併刪除。作為收件人時，瓶子回到海裡。

## 5. 資料層

| 資料表 | 欄位 |
| :---- | :---- |
| `drift_bottles` | `id` uuid、`sender_id` 外鍵 cascade、`recipient_id` 可為空外鍵 nullOnDelete、`body`、`assigned_at`、`opened_at`、`reply_body` 可為空、`replied_at`、`removed_at`、`reply_removed_at`、`released_recipient_ids` json、時間戳記。 |
| `drift_bottle_reports` | `id` uuid、`bottle_id` 外鍵 cascade、`reporter_id` 外鍵 cascade、`target` 為 `bottle` 或 `reply`、`reason` 可為空、`outcome` 可為空、`reviewed_by` 可為空、`reviewed_at` 可為空、時間戳記，`bottle_id`、`reporter_id`、`target` 三者唯一。 |

- 沿用 UUIDv7 主鍵與 `foreignUuid` 外鍵，新增 migration，不修改既有 migration。
- 狀態由欄位推導，不另存：
  - 已下架：`removed_at` 不為空。
  - 已回覆：`replied_at` 不為空。
  - 已開啟：`opened_at` 不為空。
  - 已投遞：`recipient_id` 不為空。
  - 在海裡：以上皆非。
- 新增模型 `DriftBottle`、`DriftBottleReport` 與 factory，並以 `#[Fillable]` Attribute 設定。
- 新增 Artisan 指令 `drift-bottles:release`，在 `routes/console.php` 排程每小時。

## 6. 前台

沿用既有的雙語路由、`member.locale`、`member.active`、`member.verified`，路徑放在 `/member/bottles` 下，使 `robots.txt` 既有的 `/member` 前綴涵蓋。

| 名稱 | 方法與路徑 | 說明 |
| :---- | :---- | :---- |
| `member.bottles` | GET `/member/bottles` | 我的漂流瓶：收到的、丟出的、撿一個與丟一個的入口。 |
| `member.bottles.create` | GET `/member/bottles/new` | 丟瓶子表單，含行為準則勾選。 |
| `member.bottles.store` | POST `/member/bottles` | 丟出，限流每分鐘 10 次。 |
| `member.bottles.pick` | POST `/member/bottles/pick` | 撿一個，限流每分鐘 10 次。 |
| `member.bottles.show` | GET `/member/bottles/{bottle}` | 瓶子頁，收件人與寄件者看到不同內容。 |
| `member.bottles.reply` | POST `/member/bottles/{bottle}/reply` | 回覆一次。 |
| `member.bottles.report` | POST `/member/bottles/{bottle}/report` | 檢舉瓶子或回覆。 |

- 所有頁面加 `noindex`，繁體中文與英文各一組文案。
- 會員中心加入漂流瓶連結與未開啟數量。

## 7. 後台

- 新增「漂流瓶」資源，導覽群組為「會員」，列表欄位有寄件者、收件人、狀態、是否有待處理檢舉、時間。
- 篩選：狀態、是否有待處理檢舉、日期。搜尋：內容、寄件者與收件人的姓名與 Email。
- 檢視頁顯示完整內容、回覆與檢舉紀錄，動作有下架、還原。
- 檢舉紀錄以關聯管理器呈現，動作有確認違規與駁回。
- 全部唯讀，不提供新增與編輯內容。

## 8. 前置條件與風險

| 項目 | 說明 |
| :---- | :---- |
| 先送後審 | 違規內容在被檢舉前可能已被看到，管理員需在活動期間留意檢舉。 |
| 惡意檢舉 | 惡意檢舉會讓內容暫時隱藏，駁回時才還原，管理員需要覆核。 |
| 匿名濫用 | 寄件者對收件人匿名，管理員可追溯，停用會員可處理累犯。 |
| 隨機挑選效能 | 以資料庫隨機排序，會員數在千人以內可接受，更大時需改用其他取樣方式。 |
| 開啟以 GET 記錄 | 連結預覽可能代為開啟，影響釋放判斷，風險低，沿用訊息功能的做法。 |
| 網址與 Email 過濾 | 只擋明顯的字串，無法防止刻意拆開的寫法。 |

## 9. 測試

全部使用 PHPUnit feature 測試，並以 factory 建立資料。

- 丟出：成功時指派給符合資格的陌生會員、內容長度與空白驗證、未勾選行為準則被拒絕、網址與 Email 被拒絕。
- 丟出：每日 3 個上限、未驗證與停用會員不能丟、請求限流回應 429。
- 指派：排除自己、好友、待確認好友、雙向封鎖、停用、未驗證、已持有 5 個未開啟者。
- 指派：沒有符合者時留在海裡，仍算丟出成功。
- 撿取：只拿得到海裡且符合資格的瓶子、不會撿到自己的或好友的、持有達上限不能撿、每日 10 次上限、海裡沒有時不扣次數。
- 撿取：兩位會員同時撿同一個瓶子只有一位成功。
- 釋放：超過 24 小時未開啟的釋放回海裡並記錄原收件人，已開啟與已回覆的不釋放，原收件人不會再拿到。
- 回覆：只有收件人可以、只能一次、需先開啟、下架後不能回覆，回覆後雙方不能再傳。
- 匿名：寄件者與收件人的頁面都不含對方的姓名、Email、組織與會員編號。
- 非參與者與訪客：回應 404 或導向登入。
- 檢舉：收件人檢舉瓶子後立即隱藏、寄件者檢舉回覆後立即隱藏、重複檢舉只有一筆、被檢舉方不被通知。
- 通知：被指派與被回覆各寄一封不含內文的提醒信，指派提醒 15 分鐘內只寄一次，寄信失敗不影響。
- 後台：列表與檢視頁、確認違規與駁回的結果、下架與還原、唯讀、搜尋與篩選。
- 會員被刪除：寄件者的瓶子被刪除、收件人的瓶子回到海裡。
- 中英文頁面各自顯示正確語言。

## 10. 實作階段

單一階段：migration 與模型、指派與撿取與釋放、前台頁面、檢舉、通知、後台、排程與測試。
