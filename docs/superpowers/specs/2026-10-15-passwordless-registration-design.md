# 免密碼註冊與稍後設定密碼設計規格

日期：2026-10-15
狀態：待審閱

## 1. 背景與目標

目前會員註冊必須先設定密碼，之後才能用密碼或登入連結登入。年會是現場掃 QR Code 加入的情境，註冊時要求設定密碼是最大的阻力。

本規格讓會員註冊時只需姓名與 Email，註冊後透過寄到信箱的登入連結登入，登入後再自行設定密碼。已有密碼的既有會員不受影響。

成功條件：

1. 訪客只填姓名、Email 與選填的所屬社群或公司就能註冊，不需要密碼。
2. 註冊後不會立刻登入，必須點擊寄到信箱的登入連結才取得登入狀態，並同時完成 Email 驗證。
3. 會員登入後可以設定密碼，之後可以用密碼登入。
4. 沒有密碼的帳號不能用密碼登入，且失敗訊息與密碼錯誤相同。
5. 任何人都無法在證明自己擁有該信箱之前，替某個 Email 設定出一個可登入的密碼。

## 2. 已確認的決策

| 項目 | 決策 |
| :---- | :---- |
| 方案 | 免密碼註冊，登入後再設定密碼。 |
| 註冊是否自動登入 | 否，必須點擊信箱中的登入連結。 |
| 註冊是否接受密碼 | 否，註冊表單完全移除密碼欄位。 |
| 既有會員 | 保留既有密碼與登入方式，不強制變更。 |
| 登入連結 | 沿用既有規則，15 分鐘有效、單次使用、雜湊儲存。 |
| 實作階段 | 單一階段。 |

## 3. 不在範圍內

- 社群登入與雙重認證。
- 強制既有會員設定密碼，或強制定期更換密碼。
- 變更 Email。
- 登出其他裝置的 session。
- 密碼強度之外的密碼規則，如歷史密碼與過期。

## 4. 安全原則

**在證明擁有信箱之前，不能存在任何可登入的憑證。**

若註冊時就接受密碼或自動登入，攻擊者可以替受害者的 Email 先註冊，並持有密碼或已登入的 session，待受害者之後驗證信箱，攻擊者就掌握了該帳號。因此本規格採取：

- 註冊不接受密碼，也不建立 session。
- 登入狀態只能由「點擊寄到該信箱的連結」取得。
- 沒有密碼的帳號，只能透過信箱連結或重設密碼信登入。

## 5. 規則

### 5.1 註冊

- 欄位：姓名、Email，以及選填的所屬社群或公司。
- 送出後，系統一律回應「如果這個 Email 可以註冊，登入連結已經寄出」，不論該 Email 是否已註冊。
- Email 尚未註冊：建立 `is_active` 為真、尚未驗證、沒有密碼的會員，寄出登入連結。
- Email 已註冊且啟用：不建立新會員、不修改既有資料，改寄登入連結。
- Email 已註冊但已停用：不寄信，回應相同。
- Email 一律轉為小寫並去除前後空白。
- 每個 Email 每小時最多 5 次，與「要求登入連結」共用同一個計數，超過回應 429。每個 IP 每分鐘最多 5 次。
- 註冊不會登入，也不會導向會員中心。

### 5.2 登入連結

- 沿用階段二的建立與消耗邏輯，不改動。
- 註冊產生的連結與一般登入連結相同，點擊後登入並寫入 `email_verified_at`。
- 登入成功時，在 session 記錄 `member_link_login_at`，供第 5.4 節判斷。
- 登入成功後導向原本想開的頁面，沒有時導向會員中心。

### 5.3 密碼登入

- 沒有密碼的會員，密碼登入一律失敗，訊息與密碼錯誤相同，不洩漏帳號狀態。
- 已停用的會員，沿用既有規則：密碼正確才顯示停用訊息。沒有密碼的帳號永遠顯示一般失敗訊息。
- 登入頁在密碼表單下提示「還沒有設定密碼？請改用下方的登入連結。」

### 5.4 設定與變更密碼

| 會員狀態 | 設定新密碼需要 |
| :---- | :---- |
| 尚無密碼 | 已登入且已驗證 Email，不需其他驗證。 |
| 已有密碼，且 15 分鐘內用登入連結登入過 | 不需目前密碼。 |
| 已有密碼，其他情況 | 必須輸入目前密碼。 |

- 新密碼至少 8 個字元並需要確認欄位，沿用註冊的規則。
- 設定成功後重新產生 session 識別碼，並顯示成功訊息。
- 已有密碼者輸入錯誤的目前密碼，回應驗證錯誤，不變更密碼。

### 5.5 忘記密碼與重設密碼

- 沒有密碼的會員也可以使用，等同「設定密碼」。
- 重設成功代表擁有信箱，若尚未驗證則一併寫入 `email_verified_at`。

### 5.6 會員中心提示

- 尚無密碼的會員，會員中心顯示「設定密碼」提示與連結。
- 已設定密碼者只在選單提供「變更密碼」連結。

## 6. 資料層

- `members.password` 改為可為空，新增 migration，不修改既有的建立資料表 migration，因為該資料表已在正式環境建立。
- 模型的 `password` cast 維持 `hashed`，空值不雜湊。
- `MemberFactory` 新增 `passwordless()` 狀態。
- 新增 `Member::hasPassword(): bool`。

## 7. 前台

沿用既有的雙語路由與 `member.locale`、`member.active` middleware。

| 名稱 | 方法與路徑 | 說明 |
| :---- | :---- | :---- |
| `member.register.store` | POST `/register` | 修改：免密碼註冊，寄出登入連結 |
| `member.register.sent` | GET `/register/sent` | 新增：「請到信箱查看」的結果頁，訪客限定 |
| `member.password.edit` | GET `/member/password` | 新增：設定或變更密碼頁，需登入且已驗證 |
| `member.password.change` | PUT `/member/password` | 新增：送出，限流每位會員每分鐘 5 次 |

- 註冊成功導向 `member.register.sent`，頁面不顯示該 Email 是否已註冊。
- 設定密碼頁在已有密碼且不在 15 分鐘窗口內時，顯示「目前密碼」欄位，否則不顯示。
- 所有新頁面加 `noindex`，繁體中文與英文各一組文案。

## 8. 後台

- 會員檢視頁與列表新增唯讀的「已設定密碼」指示，只顯示是否已設定，不顯示任何雜湊。
- 後台依然不提供新增會員與修改密碼。

## 9. 前置條件與風險

| 項目 | 說明 |
| :---- | :---- |
| 帳號只靠信箱保護 | 沒有密碼的帳號，信箱被入侵就會被入侵，設定密碼不會改變，只是多一種登入方式。 |
| 郵件依賴 | 註冊完全依賴寄信，Mailgun 故障時無法註冊。寄信失敗時回應與成功相同，會員需稍後再試。 |
| 郵件量 | 註冊與登入連結共用每小時 5 封的上限，濫用者可以用他人 Email 觸發寄信，每個 Email 每小時最多 5 封。 |
| 既有的待驗證會員 | 已註冊但尚未驗證、且有密碼的會員仍可用密碼登入並看到驗證提示，行為不變。 |
| 掃碼流程 | 新會員掃 QR Code 後，需要在同一個瀏覽器開啟信中的連結，才能回到加好友頁，否則落在會員中心。 |
| 其他裝置 | 設定密碼不會登出其他裝置，不在範圍內。 |

## 10. 測試

全部使用 PHPUnit feature 測試，並以 factory 建立資料。

- 註冊：只填姓名與 Email 成功、建立未驗證且無密碼的會員、不建立 session、寄出一封登入連結。
- 註冊：表單沒有密碼欄位，送出 `password` 參數也不會被儲存。
- 註冊：Email 已註冊時不建立第二筆、不修改既有姓名與社群、寄出登入連結，回應與未註冊相同。
- 註冊：Email 已停用時不寄信，回應相同。
- 註冊：Email 大小寫與空白被正規化，與既有帳號視為同一個。
- 註冊：每個 Email 每小時第 6 次與每個 IP 每分鐘第 6 次回應 429，並與登入連結共用計數。
- 登入連結：點擊後登入並驗證 Email，session 有 `member_link_login_at`，沿用原頁。
- 密碼登入：沒有密碼的會員一律失敗，訊息與密碼錯誤相同，不拋出例外。
- 設定密碼：無密碼者登入後可直接設定並可用密碼登入。
- 設定密碼：已有密碼者需要目前密碼，錯誤時不變更，15 分鐘內用連結登入者免目前密碼，超過 15 分鐘則需要。
- 設定密碼：訪客與未驗證會員被導向，新密碼不符規則被拒絕，限流後回應 429。
- 重設密碼：無密碼者可重設並同時驗證 Email。
- 會員中心：無密碼者看到設定密碼提示，有密碼者沒有。
- 後台：顯示「已設定密碼」指示，不顯示雜湊，仍沒有修改密碼的入口。
- 預先劫持：以受害者的 Email 註冊後，攻擊者沒有任何可登入的憑證或 session。
- 中英文頁面各自顯示正確語言。

## 11. 實作階段

單一階段：migration、註冊流程、密碼設定頁、密碼登入的調整、會員中心提示、後台指示、文案與測試。
