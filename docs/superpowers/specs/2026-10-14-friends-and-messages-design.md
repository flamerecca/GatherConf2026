# 會員好友與短訊設計規格

日期：2026-10-14
狀態：待審閱

## 1. 背景與目標

官網已有獨立的 `Member` 與 `member` guard，會員可註冊、登入與驗證 Email。年會是面對面的活動，會員之間目前沒有任何互動方式。

本規格新增「好友」與「站內短訊」：會員以專屬的加好友連結或 QR Code 互相邀請，接受後成為好友，好友之間可以互傳純文字短訊。後台可以審閱好友關係與訊息，用於處理濫用。

成功條件：

1. 會員可以取得自己的加好友連結與 QR Code，另一位會員掃描或點擊後可以送出邀請。
2. 邀請必須經對方接受才成為好友，被邀請者可以接受、忽略或封鎖。
3. 只有好友之間可以互傳短訊，並有已讀狀態、未讀數與不含內容的 Email 提醒。
4. 會員可以移除好友與封鎖，封鎖後對方無法再邀請或傳訊。
5. 後台管理者可以檢視好友關係與訊息內容。

## 2. 已確認的決策

| 項目 | 決策 |
| :---- | :---- |
| 找人方式 | 只有專屬連結與 QR Code，不提供會員名錄與搜尋。 |
| 成立方式 | 邀請後需對方接受。 |
| 短訊 | 站內純文字，只有好友之間可以傳送，不是手機簡訊。 |
| 功能 | 已讀狀態與未讀數、新訊息 Email 通知、移除好友與封鎖、後台可審閱訊息。 |
| 即時性 | 不做即時推播，重新整理頁面即可看到新訊息。 |
| QR Code 套件 | `chillerlan/php-qrcode` 已因 Filament 間接安裝，改列為直接相依性，不下載新套件。 |
| 訊息保留 | 訊息以會員配對為單位保存，移除好友後仍保留，供後台處理檢舉。 |
| 實作階段 | 階段一為好友，階段二為短訊與後台。 |

## 3. 不在範圍內

- 即時推播、WebSocket 與瀏覽器通知。
- 附件、圖片、表情貼圖與連結預覽。
- 群組、聊天室與廣播。
- 訊息的編輯、撤回與刪除。
- 會員檢舉按鈕，濫用處理目前靠封鎖與後台審閱。
- 會員名錄、搜尋與推薦好友。
- 後台對會員代為傳訊。

## 4. 規則

### 4.1 使用資格

- 只有已登入、已驗證 Email 且為啟用狀態的會員可以使用好友與短訊。
- 已停用的會員不出現在任何人的好友清單中，無法傳送或接收，其歷史訊息保留。

### 4.2 加好友連結

- 每位會員有一個 `friend_code`，32 個字元的隨機英數字，在註冊時產生，既有會員由 migration 補齊。
- 連結為 `/friends/add/{code}` 與 `/en/friends/add/{code}`。QR Code 的內容是該連結的完整網址。
- 會員可以隨時重新產生，舊連結與舊 QR Code 立即失效。
- 連結不含也不顯示會員的 Email。
- 加好友頁只顯示對方的姓名與所屬社群，並提供「送出好友邀請」按鈕。
- 在以下情況，加好友頁一律回應 404，不顯示原因，避免洩漏封鎖或停用狀態：
  - 連結不存在或已失效。
  - 擁有者已停用。
  - 擁有者已封鎖你，或你已封鎖擁有者。
- 打開自己的連結時，顯示「這是你自己的連結」，不提供邀請按鈕。
- 未登入時導向登入頁，登入後回到加好友頁。未驗證 Email 的會員先導向驗證頁。

### 4.3 好友關係

| 情境 | 結果 |
| :---- | :---- |
| 送出邀請 | 建立一筆 `pending`，記錄邀請者。 |
| 對同一人重複送出，或對方已先邀請你 | 不重複建立。若對方已邀請你，視為接受。 |
| 已是好友 | 不建立，顯示「已經是好友」。 |
| 接受 | 狀態改為 `accepted`，記錄回應時間。 |
| 忽略 | 刪除該筆邀請，不通知邀請者，邀請者之後可以再送。 |
| 取消自己送出的邀請 | 刪除該筆邀請。 |
| 移除好友 | 刪除該筆關係，不通知對方，訊息保留但雙方的清單不再顯示對話。 |
| 重新成為好友 | 之前的訊息重新出現在對話中。 |

- 每一對會員在 `friendships` 只會有一列，以較小與較大的會員 id 做唯一約束。
- 同時處理的並發請求不得產生兩列，由唯一約束保證。

### 4.4 封鎖

- 封鎖只能從好友清單或收到的邀請上操作，對象必須是目前的好友或寄來待處理邀請的會員。
- 封鎖會立即刪除雙方之間的好友關係與待處理邀請。
- 封鎖後，被封鎖者不能邀請封鎖者，也不能傳訊給封鎖者，並且不會被告知。
- 封鎖者可以在「我的好友」頁解除封鎖，解除後不會自動恢復好友關係。
- 被封鎖時，被封鎖者看到的行為與對方停用或連結失效相同，不顯示封鎖。

### 4.5 短訊

- 只有 `accepted` 的好友，且雙方皆啟用、任何一方都沒有封鎖對方時，才能傳送。
- 內容為純文字，去除前後空白後 1 到 1000 個字元，換行保留，一律跳脫輸出，不解析連結。
- 每位寄件者每分鐘最多 20 則，超過回應 429。
- 開啟對話頁時，把該好友寄給自己的未讀訊息標記為已讀。
- 未讀數只計算來自目前好友、未封鎖、啟用的會員的未讀訊息。
- 對話頁預設顯示最新 50 則，由舊到新排列，提供「載入更早的訊息」。

### 4.6 Email 通知

- 收到新訊息時寄一封提醒信給收件者，信中只說明「某某傳了一則新訊息」，不含訊息內容。
- 同一寄件者對同一收件者，15 分鐘內最多寄一封提醒。
- 收件者已停用時不寄。
- 寄信失敗不得讓傳送失敗，記錄錯誤後照常回應，作法與登入連結相同。
- 通知信使用繁體中文，收件者的語系偏好目前不記錄。

### 4.7 隱私說明

- 對話頁顯示一行說明：「訊息可能因管理與檢舉處理而由管理者檢視。」英文頁為對應的翻譯。
- 建議在使用條款或隱私說明中一併載明，該文件不在本規格範圍內。

## 5. 資料層

### 5.1 `members` 新增欄位

| 欄位 | 型別 | 說明 |
| :---- | :---- | :---- |
| `friend_code` | string 32，唯一 | 加好友連結的隨機碼 |

模型在 `creating` 事件為沒有值的會員產生，並提供 `regenerateFriendCode(): void`。既有會員於 migration 中逐筆補齊，欄位先建立為可為空，補齊後改為不可為空。

### 5.2 `friendships`

| 欄位 | 型別 | 說明 |
| :---- | :---- | :---- |
| `id` | bigint | 主鍵 |
| `member_low_id` | foreignId | 較小的會員 id，刪除會員時一併刪除 |
| `member_high_id` | foreignId | 較大的會員 id，刪除會員時一併刪除 |
| `requester_id` | foreignId | 邀請者，必為上面兩者之一 |
| `status` | string | `pending` 或 `accepted` |
| `responded_at` | timestamp，可為空 | 接受時間 |
| `created_at`、`updated_at` | timestamp | 時間戳記 |

`member_low_id` 與 `member_high_id` 組成唯一索引，兩者各自另有索引。

### 5.3 `member_blocks`

| 欄位 | 型別 | 說明 |
| :---- | :---- | :---- |
| `id` | bigint | 主鍵 |
| `blocker_id` | foreignId | 封鎖者，刪除會員時一併刪除 |
| `blocked_id` | foreignId | 被封鎖者，刪除會員時一併刪除 |
| `created_at` | timestamp | 建立時間 |

`blocker_id` 與 `blocked_id` 組成唯一索引。

### 5.4 `messages`

| 欄位 | 型別 | 說明 |
| :---- | :---- | :---- |
| `id` | bigint | 主鍵 |
| `sender_id` | foreignId | 寄件者，刪除會員時一併刪除 |
| `recipient_id` | foreignId | 收件者，刪除會員時一併刪除 |
| `body` | text | 內容 |
| `read_at` | timestamp，可為空 | 已讀時間 |
| `created_at` | timestamp | 傳送時間 |

`recipient_id` 與 `read_at` 組成索引，用於未讀數；`sender_id`、`recipient_id` 與 `id` 組成索引，用於對話串。

### 5.5 模型與工廠

- 新增 `Friendship`、`MemberBlock`、`Message`，使用 `#[Fillable]` 與 `#[Hidden]` 屬性，見 `.ai/rules/models.md`，並提供 factory。
- `Member` 新增關聯與查詢方法：`friends()`、`pendingInvitationsReceived()`、`pendingInvitationsSent()`、`hasBlocked(Member)`、`isBlockedBy(Member)`、`isFriendWith(Member)`。

## 6. 前台

所有路由沿用現有雙語結構，中文版 `member.<name>`，英文版加 `.en`，英文路徑加 `/en`，並套用 `member.locale`、`member.active` 與 `auth:member`。新增 middleware 別名 `member.verified`，未驗證的會員導向本地化的驗證提示頁，並套用在本節所有路由。

| 名稱 | 方法與路徑 | 說明 |
| :---- | :---- | :---- |
| `member.friends` | GET `/friends` | 我的好友，含 QR Code、清單、邀請與封鎖名單 |
| `member.friends.code.regenerate` | POST `/friends/code` | 重新產生加好友連結 |
| `member.friends.add` | GET `/friends/add/{code}` | 加好友頁 |
| `member.friends.invite` | POST `/friends/add/{code}` | 送出邀請 |
| `member.friends.accept` | POST `/friends/{friendship}/accept` | 接受 |
| `member.friends.decline` | DELETE `/friends/{friendship}` | 忽略、取消或移除好友 |
| `member.friends.block` | POST `/friends/{member}/block` | 封鎖 |
| `member.friends.unblock` | DELETE `/friends/{member}/block` | 解除封鎖 |
| `member.messages.show` | GET `/messages/{friendship}` | 對話頁 |
| `member.messages.store` | POST `/messages/{friendship}` | 傳送 |

- 路徑中的 `{friendship}` 與 `{member}` 以 id 綁定，授權一律以「目前會員是否為該關係的一方」檢查，不屬於自己的回應 404。
- 封鎖與解除封鎖的 `{member}` 必須是目前的好友、對自己有待處理邀請的人，或已被自己封鎖的人，其他情況回應 404，避免用 id 探測會員。
- 傳送頁面的表單以 `POST` 提交，成功後導回對話頁，並保留輸入錯誤。
- 會員中心與頁面選單顯示未讀訊息數與待處理邀請數。

### 6.1 QR Code

- 由伺服器以 `chillerlan/php-qrcode` 產生 SVG，直接內嵌在頁面，不向外部服務請求。
- 糾錯等級 M，顏色使用設計系統的 `ink` 與 `parchment` 並確保對比，在淺色與深色模式下都能被掃描，必要時以白色底與安靜區包住。
- 頁面同時顯示連結文字與「複製連結」按鈕。

## 7. 通知

新增 `NewMessageNotification`，只有 `mail` 通道，同步寄送，內容不含訊息。連結指向 `member.messages.show` 的本地化路由，未登入時會先導向登入。

## 8. 後台

在 Filament 新增兩個唯讀資源，放在「會員」導覽群組。

**好友關係**

- 欄位：邀請者、對方、狀態、建立時間、回應時間。
- 搜尋：兩方的姓名與 Email。篩選：狀態。
- 不提供建立、編輯與刪除。

**訊息**

- 欄位：寄件者、收件者、內容摘要、傳送時間、已讀時間。
- 搜尋：兩方的姓名與 Email、內容。篩選：日期範圍、已讀狀態。
- 檢視頁顯示完整內容與同一配對的前後訊息。
- 不提供建立、編輯與刪除。

後台存取沿用 `auth.admin_emails` 名單。

## 9. 前置條件與風險

| 項目 | 說明 |
| :---- | :---- |
| 隱私 | 管理者可以閱讀會員之間的訊息，需在對話頁揭露，並建議載明於使用條款。 |
| 連結外洩 | 連結或 QR Code 被他人取得時，對方只能送出邀請，仍須經你接受，且可重新產生。 |
| 騷擾 | 以封鎖、頻率限制與後台審閱因應，檢舉按鈕不在本次範圍。 |
| 郵件量 | 提醒信有 15 分鐘節流，仍依賴 Mailgun 額度。 |
| 資料量 | 訊息只增不減，目前規模小，不處理封存。 |
| 相依性 | `chillerlan/php-qrcode` 需列為直接相依性，版本維持目前鎖定的 5.0.5。 |

## 10. 測試

全部使用 PHPUnit feature 測試，以 factory 建立資料。

**階段一**

- 註冊與既有會員都有唯一的 `friend_code`，重新產生後舊連結回應 404。
- 加好友頁：顯示姓名與所屬社群、不顯示 Email、擁有者停用或雙方封鎖時 404、自己的連結不提供邀請。
- 未登入導向登入並回到加好友頁，未驗證導向驗證頁。
- 邀請：建立 `pending`、重複不重複建立、對方已邀請視為接受、已是好友不建立。
- 接受、忽略、取消與移除好友，且不屬於自己的關係回應 404。
- 封鎖：刪除好友關係與邀請、被封鎖者看不到邀請入口、解除封鎖不恢復好友。
- 並發送出邀請只會有一列。
- QR Code 內容為本地化的加好友網址，且頁面不含外部請求。

**階段二**

- 傳訊：只有好友可傳、非好友與封鎖回應 403 或 404、空白與超過 1000 字被拒絕、內容被跳脫。
- 頻率限制：每分鐘第 21 則回應 429。
- 已讀：開啟對話標記已讀，只影響自己收到的訊息，未讀數正確。
- 移除好友後對話消失，重新成為好友後歷史訊息回來。
- 停用會員不出現在清單、無法傳送，其訊息保留。
- Email 提醒：不含內容、15 分鐘內只寄一封、收件者停用不寄、寄信失敗不影響傳送。
- 後台：兩個資源只有管理者可以進入、唯讀、搜尋與篩選正確，會員無法進入。
- 中英文頁面各自顯示正確語言，通知信連結為本地化網址。

## 11. 實作階段

1. **階段一**：直接相依性、`friend_code`、`friendships`、`member_blocks`、加好友頁、邀請流程與「我的好友」頁，含 QR Code。
2. **階段二**：`messages`、對話頁、已讀與未讀數、Email 提醒、後台兩個資源。

兩個階段各自產出實作計畫與提交，階段一完成並驗證後再開始階段二。
